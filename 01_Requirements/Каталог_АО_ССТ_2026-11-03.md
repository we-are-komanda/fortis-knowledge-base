## История и текущая библиотека

Актуальный каталог и сохранённый снимок проекта имеют разное назначение. В панели библиотеки показываются только ID последнего успешно загруженного каталога для текущего проекта. Исторические карточки остаются в `DefenseProject.assetLibrary` для отображения ранее размещённых объектов, расчётов и экспорта. Загрузка каталога не удаляет историю, не меняет экземпляры и не сохраняет проект на сервер автоматически. Пустой актуальный каталог означает пустую панель, а не возврат старых средств.

Прежние 34 demo-ID продолжают распознаваться как demo при импорте старых проектов; новые SST-ID не наследуют этот признак. Исторический набор сохранён отдельно в test fixtures. Неиспользуемый путь загрузки старых demo-пресетов в GIS удалён, чтобы он не создавал размещения со ссылками на отсутствующие карточки. Импорт сохранённого `DefenseProject` остаётся.

## Локальное применение

Перед заменой создан полный PostgreSQL backup: `.fortis-dev/catalog-replacement-2026-11-03/before.dump` (игнорируется Git, права 0600). Там же находятся JSON до/после, исходные payload и ответы создания. Подтверждено, что БД и HTTP API локальные (`127.0.0.1`).

Через существующий API сначала созданы и прочитаны шесть новых карточек; затем удалены 34 старые. Итоговый GET возвращает ровно шесть SST-карточек. Список двух существующих проектов и их версии до/после совпадают. Исходный frontend-каталог и обычный seed используют тот же набор.
