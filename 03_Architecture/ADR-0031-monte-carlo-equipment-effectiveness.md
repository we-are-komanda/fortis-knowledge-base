# ADR-0031 — характеристики и позиции размещённых средств в Монте-Карло

Дата: 2026-11-04. Статус: принято по запросу пользователя.

## Контекст

[[ADR-0029-map-monte-carlo-shared-project]] дал Монте-Карло общую с картой конфигурацию `DefenseProject`: позиции, ID и количества размещений уже переводились в локальную систему объекта (`buildProjectScenario`), но эффект был явным ограничением: «средства визуализируются, но их ТТХ, вероятность обнаружения/перехвата и эффективность не участвуют в расчёте».

Пользователь запросил обратное: моделирование должно оценивать эффективность собранной конфигурации. Выбранный подход после уточнения: покрытие + условная вероятность нейтрализации; для изделий без вычисленной дальности (каталог АО «ССТ», `coverageType=none`, [[Каталог_АО_ССТ_2026-11-03]]) дальность вводится на размещённом объекте.

## Решение

Модель поднята до `mass-motion@4` с подключённой условной моделью эффективности `coverage-neutralization@1`.

### Источник параметров

`buildProjectScenario` для каждого размещения вычисляет эффективное условное покрытие:

1. `customCoverageRadius` размещения (`ADR-0009`: настройки живут в размещённом инстансе);
2. иначе значение каталога, но только для `coverageType` круг/сектор; `none`, `line`, `polygon` не дают радиуса;
3. угол: `customCoverageAngle`, иначе для сектора — `coverageAngle` каталога, иначе 360°;
4. участвуют размещения со статусом `active` (действует) и `planned` (запланировано); `inactive` и `maintenance` — нет; участие требует радиус > 0 и количество ≥ 1.

Позиции — те же локальные метры относительно центра объекта, что и остальная сцена; поворот размещения задаёт направление сектора (0° = север, по часовой стрелке).

### Вероятностная модель

Объекты двигаются по прежним радиальным траекториям (потоки времени и направлений не менялись). Изменения:

- Для каждой пары «объект–юнит» ищется первое пересечение траектории с окружностью условной зоны (отрезок × окружность, квадратное уравнение) с проверкой сектора; параметр даёт точку и момент условной нейтрализации.
- Покрывающие юниты суммируются как независимые: k = Σ количества всех покрывающих размещений; условная вероятность нейтрализации объекта `P = 1 − 0.5^k` (`effectModel.unitProbability = 0.5`).
- Один seeded-розыгрыш на объект из выделенного потока (`runSeed ^ 0x51ed270b`); количество получаемых из потока значений не зависит от конфигурации покрытий, поэтому добавление средства может только усилить исход, а маршруты и расписание не меняются.
- Нейтрализованный объект исчезает в точке и момент входа в зону, не достигает границы и не создаёт «условное срабатывание»; достигшие границы — по-прежнему «прорвавшиеся» (счётчик «Условные срабатывания»).

### Допущения (модель, а не данные)

- Зоны дальности/угла — оценки пользователя или каталога; `0.5` — единая условная вероятность за проход одного учитываемого изделия. Это учебные допущения модели, не подтверждённая эффективность реальных средств (соответствует ограничениям [[Продуктовый_план_Fortis]] и FRC-11 honest surface).
- Детекция как отдельный исход не моделируется: пока эффект один — нейтрализация.

### UI

- Боковая панель Монте-Карло: раздел «Эффективность средств» — на каждое размещение строка со статусом, бэйдж «учитывается/не участвует» и поля «Дальность, м» / «Угол, °» с немедленной записью через `updatePlacedObject` (без автосохранения проекта; явное сохранение остаётся у пользователя).
- Счётчики прогона: добавлен «Нейтрализованы»; пакетная сводка получила медиану и p90 доли нейтрализованных (`neutralizedRates`).
- Справка: разделы «Журнал нейтрализаций» (последние 5, переход к моменту нейтрализации), описание модели, список участников с параметрами; прежний текст о неучёте ТТХ заменён.
- 2D: пунктирные круги/клинья условных зон участвующих средств; нейтрализованные объекты показываются крестом; в 3D изменён цвет/масштаб (`#7c3aed`, светлее в тёмной теме).

## Границы

- Формат backend API, контракт `DefenseProject`, версия схемы и правила сохранения не меняются: `customCoverageRadius/Angle`, статусы и количества уже есть в schemaVersion 1.
- Desktop/offline demo не пересобирается как поставка; изменение влезает в существующую поставку при следующей сборке.
- Результат пакетов за тот же seed отличается от `mass-motion@3`: версии модели сравниваются только внутри своей версии.

## Проверки

- Unit: `mass-motion.test.ts` (детерминизм розыгрышей, независимость маршрутов от покрытий, точка/момент нейтрализации, сектора, монотонность по количеству юнитов, валидация юнитов), `project-scenario.test.ts` (источник параметров: override vs каталог vs `none`, статусы, локальные юниты).
- `tsc --noEmit`, ESLint изменённых файлов, `next build`.
- Browser: `test/playwright/map-modeling.cjs` (регрессия ADR-0029), `test/playwright/mass-motion.cjs`, новый `test/playwright/mc-effectiveness.cjs`: флаги участия, зоны в 2D, счётчики, пакетная доля (k=4 → ~93.8%), журнал нейтрализаций в модальном окне, без записей API и ошибок страницы.

## Связи

Реализует оставшееся ограничение [[ADR-0029-map-monte-carlo-shared-project]]; уточняет [[ADR-0005-defense-project-placement-authority]] (настройки инстанса) и [[Каталог_АО_ССТ_2026-11-03]] (дальности не вычисляются автоматически, вводятся пользователем).
